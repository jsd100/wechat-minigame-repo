# 开发排障与测试手册

本手册面向接手本仓库的开发者和 AI Agent，用《早点凑一单》演示如何复现、截图、定位和验收。旧设计稿和截图使用开发名《摊位凑一单》。工具安装、MCP 注册与凭证管理见[环境使用说明](../环境使用说明.md)。历次游戏验收见[小样验收记录](superpowers/verification/2026-11-20-breakfast-stall-sample.md)。命令默认在仓库根目录的 macOS 终端执行。

## 1. 先确定工具和目标路径

| 想查什么 | 用什么 | 传什么路径 |
| --- | --- | --- |
| 3D 场景、相机、节点、贴图引用 | Cocos Creator 3.8.8 与 Cocos MCP | Creator 打开 `games/breakfast-stall/`，从 `assets/main.scene` 和源码检查 |
| 微信小游戏的实际渲染、触控、控制台 | 微信开发者工具和 `wechatide` | 《早点凑一单》传 `games/breakfast-stall/build/wechatgame-breakfast-release/` 的绝对路径。原生 2D 小游戏传含 `game.js` 的运行目录 |
| 原生小程序页面、表单和导航 | 微信开发者工具和 `wechatide` | 传含小程序 `project.config.json` 的绝对目录，核对 `miniprogramRoot`。页面操作用 selector |
| 快速看本地画面、试不同屏幕比例 | Creator 浏览器预览、浏览器测试工具，或小游戏助手 MCP | Creator 使用预览 URL；小游戏助手 `run_game` 的 `workspacePath` 为包含 `game.js` 的构建目录 |
| 选单、暂存、撤回、自动换单和存档规则 | TypeScript 与 `node --test` | 直接跑 `games/breakfast-stall/tests/`，可以独立于 GUI 验证状态 |

微信模拟器和 Creator 浏览器预览各有存档。先从本次画面记录关卡、当前订单、是否已有暂存、手机模板和动效设置。新包可能直接打开已解锁的最高关。需要切换关卡时优先走界面上的「上一关」「下一关」「重开本关」。覆盖存档的测试放在独立浏览器预览环境，别清用户的微信数据来凑测试前置条件。

## 2. Cocos Creator 与 MCP

### 检查场景、重新导入和预览

Creator 里的「场景」回答模型放在哪里；运行中的微信画面回答玩家实际看见什么。两者都要核对，尤其是这个项目的游戏对象与界面由运行脚本创建。

```bash
# Creator 尚未打开时运行；随后等工程完成导入。
npm run dev:cocos:breakfast
curl -fsS http://127.0.0.1:3000/health
```

在任何支持 MCP 的 Agent 中，通过已配置的 `cocos-creator` 连接 `http://127.0.0.1:3000/mcp`。优先读下列资源，或按客户端列出的工具名称调用。`/health` 能查连通性，工程和场景还要用资源或工具结果核对。

| MCP 方法或工具 | 示例参数 | 何时用 |
| --- | --- | --- |
| `resources/read` | `{"uri":"cocos://project/info"}` | 核对项目名与实际打开的源码目录 |
| `resources/read` | `{"uri":"cocos://scene/hierarchy"}` | 核对 `Main Camera`、`Main Light`、`Breakfast Game` |
| `scene_manage` | `{"action":"hierarchy","includeComponents":true}` | 查节点对应组件，资源列表不可用时也可调用 |
| `project_refresh_assets` | `{}` | 改 TypeScript 或 PNG 后通知编辑器重新导入，尤其要确认新文件生成了 `.meta` |
| `debug_preview` | `{"action":"start"}` | 快速看编辑器内运行状态 |
| `debug_screenshot` | `{"target":"window"}` | 截 Creator 编辑器窗口。微信画面另走微信截图接口 |
| `builder_manage` | `{"action":"open_panel"}` | 需要手动构建时打开 Build 面板 |

客户端没接入 MCP、但能在运行 Creator 的 Mac 上执行命令时，可以用 Node 内置 `fetch` 走同一个端点。下面两次业务调用均为只读，可原样粘贴。

```bash
node --input-type=module <<'JS'
const endpoint = 'http://127.0.0.1:3000/mcp';
const headers = { 'Content-Type': 'application/json', Accept: 'application/json, text/event-stream' };
let id = 0;
async function rpc(method, params, notification = false) {
  const body = { jsonrpc: '2.0', method, params, ...(notification ? {} : { id: ++id }) };
  const response = await fetch(endpoint, { method: 'POST', headers, body: JSON.stringify(body) });
  const session = response.headers.get('mcp-session-id');
  if (session) headers['Mcp-Session-Id'] = session;
  const raw = await response.text();
  if (!response.ok) throw new Error(`MCP HTTP ${response.status} ${raw}`);
  if (notification) return;
  const payload = raw.trim().startsWith('{') ? raw : raw.split('\n').find(line => line.startsWith('data: '))?.slice(6);
  const reply = JSON.parse(payload);
  if (reply.error || reply.result?.isError) throw new Error(JSON.stringify(reply));
  return reply.result;
}
await rpc('initialize', { protocolVersion: '2025-03-26', capabilities: {}, clientInfo: { name: 'breakfast-qa', version: '1.0.0' } });
await rpc('notifications/initialized', {}, true);
console.log(JSON.stringify(await rpc('resources/read', { uri: 'cocos://project/info' }), null, 2));
console.log(JSON.stringify(await rpc('tools/call', { name: 'scene_manage', arguments: { action: 'current' } }), null, 2));
JS
```

### 构建并核对微信发布包

用同一配置做复现和修复复测，日志和图分开保存。项目脚本把 Creator CLI 的成功退出码 `36` 转为 `0`，并检查微信入口文件、启动图和首屏脚本。想复现发布包专有的问题时，要运行发布模式。

```bash
mkdir -p "$PWD/.tooling/local"
qa_dir=$(mktemp -d "$PWD/.tooling/local/breakfast-qa.XXXXXX")
wx_build="$PWD/games/breakfast-stall/build/wechatgame-breakfast-release"
printf '本轮证据目录 %s\n' "$qa_dir"

if npm run build:breakfast > "$qa_dir/build.log" 2>&1; then
  tail -8 "$qa_dir/build.log"
  ls -lT "$wx_build/game.js" "$wx_build/game.json" "$wx_build/project.config.json"
else
  tail -50 "$qa_dir/build.log"
  false
fi
```

继续前核对三点。日志有本次构建结束记录，三个文件更新时间和本次运行一致，产物 `project.config.json` 的 `compileType` 是 `game` 且 AppID 与 [发布配置](../games/breakfast-stall/build.wechatgame.release.json) 一致。编辑器存在已知的本地插件警告时，以构建结果和目标功能的实际画面判断影响。

### 修改和验收微信启动页

启动页以笑脸包子图标和早餐摊美术为参考，由 ImageGen 生成 [无字底图](../games/breakfast-stall/extensions/breakfast-startup/breakfast-start-art.jpg)。脚本叠加简体中文招牌及加载文案，生成微信包使用的 [breakfast-start.jpg](../games/breakfast-stall/extensions/breakfast-startup/breakfast-start.jpg)。修改招牌名时，同步更新 `OrderHud.ts` 的正式关卡招牌，从仓库根目录重出图片，再重新打包。出图需要 ImageMagick，构建使用仓库已有的 JPG。macOS 默认使用系统宋体和冬青黑体，其他机器可通过 `BREAKFAST_DISPLAY_FONT`、`BREAKFAST_BODY_FONT` 指定支持简体中文的字体文件。

```bash
bash games/breakfast-stall/tools/make-breakfast-start-art.sh '早点凑一单'
npm run build:breakfast
```

项目扩展 `breakfast-startup` 在 Creator 的微信构建结束时配置产物中的 `first-screen.js`。启动图和进度条在加载引擎时显示，结束后直接开局。Creator 编辑器的场景预览跳过这层首屏。从 Creator 图形界面构建时，在扩展管理器确认「早餐摊微信启动页」已启用。构建日志出现 `[breakfast-startup] 已应用微信启动页` 后，用微信开发者工具打开新产物。

复测时从模拟器重新编译，观察加载后能否进入关卡，再点问号验证触控。如果启动图闪过太快，可以在本地浏览器用临时 Canvas 加载产物的 `first-screen.js`。给脚本提供 `window.canvas`、`module.exports`，调用 `start('default', 'default', 'false')` 后调用 `setProgress(0.62)` 截图，最后调用 `end()`。这能固定加载帧、检查不同屏幕比例。微信客户端在游戏包运行之前显示的系统画面由微信管理。

## 3. 用微信开发者工具抓复现步骤

微信工具要在能访问本机桌面的终端运行。通过项目的 `wechatide-skill` 选用 `compiler`、`automator` 和 `debugger`。示例客户端是 `codex`，其他 Agent 用其实际授权名称设置 `WX_IDE_CLIENT`。用本机报告的 Skill 版本替换 `0.3.11`。账号凭证由环境说明中的方式提供，向团队共享的日志只保留有关片段。

```bash
wx_client="${WX_IDE_CLIENT:-codex}"
wechatide -c "$wx_client" check_wechatide_status --skill-version 0.3.11

# 当前产物尚未打开时执行 open_project_window。
wechatide -c "$wx_client" open_project_window --project "$wx_build" --window-mode fullMode
wechatide -c "$wx_client" simulator_refresh --project "$wx_build"
```

状态检查应显示登录有效、版本可用。收到 `simulator_refresh` 成功后，截图看新画面是否真的加载。刚刷新可能先截到黑屏或加载态，等关卡标题和物料完整显示再开始点。连接不上时，先看当前项目窗、服务端口和实际路径，遵循本机客户端的权限提示。

```bash
wx_shot() {
  wechatide -c "$wx_client" simulator_screenshot --project "$wx_build" \
    --wait 0.5 --path "$qa_dir/$1.jpg"
}

wx_tap_image() {
  wechatide -c "$wx_client" automation_game_action --project "$wx_build" \
    --action tap --x "$1" --y "$2" --coordinate-space image \
    --image-width "$3" --image-height "$4" --wait 0.4
}

wx_shot 01-before
```

1. 查看 `01-before.jpg` 和工具返回的 `imageWidth`、`imageHeight`。坐标取自这张完整截图，`wx_tap_image` 依次接收点击的 X、Y、宽、高。每换一次设备模板、窗口比例或截图优化设置，都重新取尺寸和坐标。截图经裁切或在聊天里缩放过时，重新拍一张再取点。
2. 先逐个点击，确定位置和预期状态。点击命令的 `ok: true` 或 `status: 0` 只证明触控已发送。实际通过以订单勾选、物料入碟、关卡编号、提示文字或结算状态变化为准。`--wait` 在操作前等待，动画尚未结束时适当加长；批量脚本也要在关键点留截图。
3. 成功复现后保存 `02-repro.jpg`。改源码、重建、刷新，在相同关卡和设置下重复动作并保存 `03-after.jpg`。历史截图用于对照，新截图用于本轮结论。

默认截图按长边 1280 优化，实际编码为 JPEG。历史 `.png` 文件名中也有 JPEG。需要像素级比较时用 `--optimize=false` 写原始 PNG。本机同一模拟器模板下，JPEG 返回 589×1280，原始 PNG 返回 612×1330。点击时用参照图对应的宽高。小游戏点击走画布坐标，原生小程序使用 `automation_element_action` 的页面 selector。

```bash
wechatide -c "$wx_client" simulator_screenshot --project "$wx_build" \
  --optimize=false --path "$qa_dir/original.png"
file "$qa_dir/original.png"
```

```bash
wx_shot 02-repro

# 保存原始响应，检查本次的错误、堆栈和动作时间。
wechatide -c "$wx_client" get_simulator_console --project "$wx_build" \
  --command 'grep -n .' > "$qa_dir/console.json"

# 只有问题涉及实际网络请求时再取网络记录。
wechatide -c "$wx_client" get_simulator_network --project "$wx_build" \
  --command 'grep -n .' > "$qa_dir/network.json"
```

控制台过滤参数是 `grep` 命令字符串。无匹配只说明过滤条件未命中。操作了几步仍看到同一画面时，先查项目路径、屏幕尺寸、坐标和时间戳，再查日志与渲染。本手册实跑时曾连续收到触摸成功，但四张 JPEG 的哈希一样。采集控制台后刷新一次，并用 `simulator_screenshot --wait 2 --optimize=false` 确认确实回到第 12 关开局；用新 PNG 的尺寸取点继续。蒸汽和光效也会改变图片哈希，最终仍按游戏状态判断。

### 复测小摊开工单和设置

1. 先截图保存正式关卡的编号、订单、台面和暂存碟状态。点招牌左侧问号，依次点试玩中的茶叶蛋、米糕、茶叶蛋。分别确认遮挡文案、米糕入碟与茶叶蛋高亮、A 单盖「齐」章和 B 单收到米糕。点「再试一次」，确认试玩恢复到初始状态。
2. 用右上角关闭按钮退出，再点齿轮。点弹窗外一件正式关卡的食物，确认只关闭了弹窗。对照最初截图，正式关卡的订单、物料和暂存状态应一致。
3. 再打开设置，点两行的左侧文字切换声音和动效。动效设为「精简」时用试玩下方按钮做完一单，确认入碟、盖戳和换单结果直接出现。刷新模拟器后核对两项开关已保存，并恢复测试前的偏好。
4. 帮助关使用 `runtime/help-demo.ts` 创建独立状态，由 `core/rules.ts` 产出和正式关卡相同的事件。若画面与状态不同步，先检查事件顺序，再检查 `OrderHud.ts` 中相应的时间线。控制台若出现开工单包子图标加载失败，核对 `opening-bun.jpg.meta` 是否以纹理导入，资源路径为 `breakfast-art/opening-bun/texture`。

## 5. 分层测试和验收顺序

### 先跑规则与类型检查

Creator 打开工程完成导入后，`games/breakfast-stall/temp/declarations/cc.d.ts` 才会生成。共享 TypeScript 由根工作区依赖提供，缺少时按环境说明恢复。测试和类型脚本会自动使用正确的临时目录与编译参数：

```bash
npm test
npm run typecheck
```

测试脚本在独立临时目录编译纯规则模块，再执行 `games/breakfast-stall/tests/*.test.cjs`；类型检查仅覆盖早餐 `assets` 和 Creator 生成的声明，不递归检查扩展。需要底层命令时，可调用游戏工作区的 `npm run test --workspace=breakfast-stall` 和 `npm run typecheck --workspace=breakfast-stall`。

关卡数或遮挡改动时，至少核对配方总量、遮挡无环、合法路线、最少暂存和老存档衔接。操作区改动时，验证点击区域与显示位置一致、边缘可点、行间空白不触发动作。图片图集改完时，以 `python3 games/breakfast-stall/tools/bake-food-contours.py` 更新轮廓，再刷新 Creator 资源库并检查模型、订单小图和入碟画面。

### 用浏览器快速测比例，再用微信包确认平台行为

- 在 Creator 顶栏选择浏览器预览，使用实际显示的本地 URL。本机曾使用 `http://127.0.0.1:7456/`，端口按实际启动结果取。Playwright 等浏览器工具可以调整视口、截屏、录取控制台和发送触摸。小游戏走 Canvas，DOM selector 适合找 `#GameCanvas`，游戏按钮的位置应从画面或 HUD 布局读取。
- 过去用 Playwright 的 Chromium CDP `Input.dispatchTouchEvent` 发送一对 `touchStart`、`touchEnd`，随后从本地预览的 `BreakfastGame` 实例核对 `state`，例如 `window.cc.director.getScene().getChildByName('Breakfast Game').getComponent('BreakfastGame')`。只在独立浏览器测试上下文构造存档或模拟底部安全区。结论注明「浏览器预览」和所测尺寸。也可从已构建的小游戏目录用 `weixin-minigame-helper.run_game` 开预览。
- Creator 浏览器预览若报 `setDesignResolutionSize`、`primitives.quad` 或 `tween` 未定义，先用浏览器日志确认是否为预览入口没有导出引擎模块。以前在隔离的浏览器测试请求中补回了 `view`、`ResolutionPolicy`、`primitives` 和 `tween` 的已有引擎导出；这是该次预览的临时处理。用微信发布包交叉验证，检查 Creator 当前预览配置与引擎模块，不把临时处理写入游戏源码。
- 微信包完成后至少手动或自动走一条核心路线，优先覆盖改动。当前可用第 7 关验证从旧进度续关和暂存自动归位，第 8 关验证卡关和撤回，第 10、11 关验证油条、红薯入碟，第 12 关验证末关结算。[第 7–12 关路线](superpowers/specs/2026-11-20-breakfast-stall-levels-7-12-design.md#通关路线与纠错验收)
- 真机验收记录机型、微信版本、冷启动、触控、安全区、帧率与切后台恢复。微信 IDE 和浏览器的结果各自标明，尤其区分模拟安全区与设备实际安全区。需要发预览码、上传、提审或发布时，按本次任务授权执行。

下面是可交给支持 Playwright 代码执行的 Agent 的例子。参数使用工具当前的 `page`，先替换预览 URL 和本轮证据目录。示例从运行时界面读取齿轮位置，所以适合当前项目的本地预览。

```javascript
async (page) => {
  await page.setViewportSize({ width: 420, height: 933 });

  });
```

```text
复现目标与起始状态（项目目录、版本、设备模板、关卡、存档/设置）
```
