# 《摊位凑一单》第 7–12 关与新品实施计划

**目标** 先接入第 7–9 关，再给第 10–12 关加入短油条和半截蒸红薯。沿用 [关卡设计稿](../specs/2026-11-20-breakfast-stall-levels-7-12-design.md) 的遮挡与解法。

所有关卡沿用两张订单、两个暂存碟、一次撤回和每关 5–7 件台面食品。第 10 关用油条替换玉米，第 11 关用红薯替换玉米，第 12 关分别用油条和红薯替换玉米和豆浆。订单和提示同步修改，复验最低暂存峰值。第 1–6 关沿用原始资产、编号与存档字段。

- [x] **关卡数据。** 在 `cocos-game/assets/breakfast/core/levels.ts` 接入第 7–12 关，添加 `oilStick`、`sweetPotato` 两个品类。按设计稿保存每条路线与危局测试。验证旧存档连续完成第 6 关后接到第 7 关、打完第 12 关停在末关。
- [x] **新品图集。** 保持前六格像素和场景贴图 UUID，把油条和红薯放入 `food-icons.png` 的第三行。`bake-food-contours.py` 输出同一张图集的格位、格子尺寸和碰撞轮廓。订单图标和 3D 网格复用生成结果。验证八种闭合网格和轮廓边界。
- [x] **界面与提示。** 关卡上限由 `LEVELS` 决定。第 7–12 关接入开局提示。卡住时根据当前订单、暂存和仍在台面的挡物提示，不引用已经取走的食物。
- [x] **运行验证。** 通过 Cocos 类型检查和现有规则回归，使用 `npm --prefix cocos-game run build:wechatgame` 生成发布包。按各关盘面的合法路线实点，验收新品订单小图、单点、入碟、撤回或自动归位，以及手机比例下的盘面间距。见[本轮验收记录](../verification/2026-11-20-breakfast-stall-sample.md)。
